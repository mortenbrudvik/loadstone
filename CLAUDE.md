# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Loadstone is a macOS menu-bar window manager (Swift 6, AppKit, Accessibility API, `LSUIElement`). It tiles the frontmost window into halves, corners, and thirds from global hotkeys or by dragging a window to a screen edge. Not sandboxed; the App Sandbox blocks the AX calls it needs.

## Commands

The Xcode project is generated by XcodeGen from `project.yml`; `project.pbxproj` is committed. Regenerate after adding, removing, or moving any source or test file, or the file is not in the build:

```bash
xcodegen generate                      # /opt/homebrew/bin/xcodegen if Homebrew is not on PATH
```

Build and test (the `Loadstone` scheme is committed under `xcshareddata` and includes the test target):

```bash
xcodebuild -scheme Loadstone -destination 'platform=macOS' build
xcodebuild -scheme Loadstone -destination 'platform=macOS' test
xcodebuild -scheme Loadstone -destination 'platform=macOS' test -only-testing:LoadstoneTests/TileLayoutTests
xcodebuild -scheme Loadstone -destination 'platform=macOS' test -only-testing:LoadstoneTests/TileLayoutTests/testHalvesCoverTheWorkArea
```

Add `-derivedDataPath <dir>` to keep build products out of `~/Library/Developer/Xcode/DerivedData`. `xcodebuild` output is verbose; filter for `error:`, `warning:`, `Executed`, and `TEST SUCCEEDED|FAILED`.

Release builds sign with the maintainer's Developer ID (`project.yml`, Release config) and fail on a machine without that certificate. To build Release elsewhere pass `CODE_SIGN_IDENTITY=- ENABLE_HARDENED_RUNTIME=NO OTHER_CODE_SIGN_FLAGS=`. Version numbers live in `project.yml` (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`).

## Architecture

Data flows in one direction: input → `WindowDirector` → `MovableWindow` (AX) → screen geometry.

- **Input.** `HotkeyCenter` registers one global hotkey per `WindowCommand` through the KeyboardShortcuts package (Carbon hotkeys; fire on key-up). `EdgeDragMonitor` owns the `SnapPreview` overlay and the mouse monitors (behind `MouseEventMonitoring`, so the setting-driven install/uninstall lifecycle is testable without Accessibility trust) but makes no decisions: it feeds events to `DragSnapTracker`, a pure state machine that resolves the window under the pointer only after the drag threshold, arms only once that window's origin has moved (so text-selection and slider drags never snap), and reads the origin only while the pointer is inside a snap zone — and then at most once per `originPollInterval` (50ms), because each read is a synchronous AX round trip on the main thread and polling at event rate stutters the drag.
- **Director.** `WindowDirector` runs a `WindowCommand` on a `MovableWindow` and returns a `CommandOutcome`; the no-argument `perform(_:)` overload resolves the focused window, beeps, logs, and triggers the Accessibility prompt. It keeps the restore ledger (first frame per `WindowIdentity`, one-shot restore, pruned when the owning process quits because macOS reuses window ids). The ledger is written *after* the window accepts a frame, never before, so a refused write or a command that never ran leaves nothing for a later Restore to act on; Restore likewise drops its entry only once the old frame has been accepted. Drag snaps pass the display the gesture ended on explicitly; the hotkey path uses the display under the window's centre.
- **AX layer.** `AXWindow` is the only file that handles Accessibility-space (top-left origin) coordinates; everything it exposes is Cocoa space. It validates the window role in its initializer, returns `AXError` from writes instead of swallowing them, wraps every frame write in a save-disable-restore of `AXEnhancedUserInterface`, applies size → position → size (apps clamp a position-first write to the old display), and resolves the private `_AXUIElementGetWindow` SPI with `dlsym` so a missing symbol degrades to a title-based identity. A 0.25s AX messaging timeout is installed at launch. `AXWindowTests` drives this file through real AX calls against windows the test host owns: a process may read and write its own Accessibility hierarchy untrusted, so those tests need no TCC grant and run in CI. What they cannot reach is another app: a refused frame, a hang past the messaging timeout, or the `AXEnhancedUserInterface` dance.
- **Geometry.** `Tile.frame(in:)` floors the left/bottom pieces and gives the remainder to the right/top ones so complementary tiles meet exactly on odd widths; `leftTwoThirds` is `2 * thirdW` wide for the same reason. `SnapZones` maps a pointer against the *full* screen frame, tiles are laid into the *visible* frame. `ScreenGeometry` flips about the primary display's top edge (`NSScreen.screens[0]`, never `NSScreen.main`). `Display` is a value snapshot of an `NSScreen` so multi-display logic is testable. `ScreenGeometry.neighbor(of:delta:in:)` walks displays in reading order (x ascending, then top before bottom), not `NSScreen.screens` order, so Next/Previous Display follow the desk layout.

### Invariants worth knowing before editing

- `WindowCommand` is the single source of truth for hotkeys, the status-bar menu, and the Shortcuts pane. Adding a `Tile` case fails to compile until `title`, `defaultShortcut`, and `section` cover it, then it appears everywhere. `WindowCommand.id` strings are the UserDefaults keys where users' custom shortcuts live (`KeyboardShortcuts_<id>`); never rename one. `WindowCommandTests` pins the list.
- Swift 6 with `SWIFT_STRICT_CONCURRENCY: complete`. Everything with state is `@MainActor`; the one deliberate `nonisolated` hop is `EdgeDragMonitor.enqueue`. Some Carbon/AX globals (e.g. `kAXTrustedCheckOptionPrompt`) are imported as mutable globals and rejected by the compiler; use their string values instead.
- Testability seams, all with production defaults: `WindowDirector(displays:)`, the `MovableWindow` protocol, `AppSettings(defaults:loginItems:)` via `LoginItemService`, `NativeTiling(defaults:marker:)`, `EdgeDragMonitor(monitors:)` via `MouseEventMonitoring`, and `DragSnapTracker<Window>` with closures plus an injected event time. Extend these rather than reaching for singletons in new code.
- Test fixtures use dimensions that do not divide by 2 or 3 (1201×901, negative-origin displays) on purpose; even fixtures hid a real rounding bug.
- `AppSettings.launchAtLogin` reassigns itself inside a method called from its own `didSet`; the `isApplyingLoginItem` guard is what stops infinite recursion. `SMAppService` can succeed and still report `.requiresApproval`, which the UI surfaces.

### System side effects

- `NativeTiling` writes `EnableTilingByEdgeDrag`/`EnableTopTilingByEdgeDrag` in the `com.apple.WindowManager` defaults domain at launch and restores the user's prior values in `applicationWillTerminate`. The capture is also parked in Loadstone's own defaults under `NativeTiling.markerKey` for the length of the run, so a force-quit or crash is detected at the next launch and undone before a new baseline is captured — without that, Loadstone would record its own `false` as "what the user had" and the change would become permanent. Tests must pass an explicit `marker:`; the production default is `UserDefaults.standard`, which under `TEST_HOST` is the real app's domain.
- Accessibility (TCC) is keyed to the code signature. Ad-hoc Debug builds get a new identity on every rebuild, which is why the alert and README say to remove and re-add the entry, and why a Debug build and the Developer ID copy in `/Applications` do not share a grant. `AccessibilityAuth.isEffectivelyTrusted` probes a real AX call because `AXIsProcessTrusted` can say yes while calls still return `.apiDisabled` until relaunch.
- KeyboardShortcuts swallows Carbon registration failures (prints to stdout, which an `LSUIElement` app discards) and still records the shortcut as registered; the effective binding per command is logged at startup as the only diagnostic.
