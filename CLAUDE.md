# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Loadstone is a macOS menu-bar window manager (Swift 6, AppKit, Accessibility API, `LSUIElement`). It tiles the frontmost window into halves, corners, and thirds from global hotkeys or by dragging a window to a screen edge. Not sandboxed; the App Sandbox blocks the AX calls it needs.

## Commands

The Xcode project is generated by XcodeGen from `project.yml`; `project.pbxproj` is committed. Regenerate after adding, removing, or moving any source or test file, or the file is not in the build:

```bash
xcodegen generate                      # /opt/homebrew/bin/xcodegen if Homebrew is not on PATH
```

Build and test (the `Loadstone` scheme is committed under `xcshareddata` and includes the test target):

```bash
xcodebuild -scheme Loadstone -destination 'platform=macOS' build
xcodebuild -scheme Loadstone -destination 'platform=macOS' test
xcodebuild -scheme Loadstone -destination 'platform=macOS' test -only-testing:LoadstoneTests/TileLayoutTests
xcodebuild -scheme Loadstone -destination 'platform=macOS' test -only-testing:LoadstoneTests/TileLayoutTests/testHalvesCoverTheWorkArea
```

Add `-derivedDataPath <dir>` to keep build products out of `~/Library/Developer/Xcode/DerivedData`. `xcodebuild` output is verbose; filter for `error:`, `warning:`, `Executed`, and `TEST SUCCEEDED|FAILED`.

Release builds sign with the maintainer's Developer ID (`project.yml`, Release config) and fail on a machine without that certificate. To build Release elsewhere pass `CODE_SIGN_IDENTITY=- ENABLE_HARDENED_RUNTIME=NO OTHER_CODE_SIGN_FLAGS=`. Version numbers live in `project.yml` (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`).

## Releasing

This is the **outside-the-App-Store** path (GitHub zip). App Store distribution is a separate track: Apple Distribution cert, sandbox, App Store Connect; notarization is not used there.

There is no release script. Do the steps below on a Mac that has:

- Xcode with Command Line Tools
- Identity `Developer ID Application: Morten Brudvik (3GS65HFAFH)` in the login keychain (`security find-identity -v -p codesigning`)
- Team ID `3GS65HFAFH`
- `gh` authenticated to `mortenbrudvik`
- A notarytool keychain profile named `loadstone` (see first-time setup below)

### First-time notarytool setup

Apple ID 2FA cannot be used directly. Create an **app-specific password** at [appleid.apple.com](https://appleid.apple.com/account/manage) → Sign-In and Security → App-Specific Passwords. It authenticates the maintainer's Apple ID to the notary service, not Loadstone users, and is not embedded in the app. Store it once:

```bash
xcrun notarytool store-credentials "loadstone" \
  --apple-id "morten@brudvik.com" \
  --team-id "3GS65HFAFH"
```

It prompts for the app-specific password and saves it in the Keychain. Later commands use `--keychain-profile "loadstone"`. Confirm with `xcrun notarytool history --keychain-profile loadstone`.

### Cut a version

1. Bump `MARKETING_VERSION` (user-facing, e.g. `0.1.2`) and `CURRENT_PROJECT_VERSION` (integer build, always increment) in `project.yml`.
2. Regenerate so the committed `project.pbxproj` matches:

```bash
xcodegen generate
```

3. Commit the bump (and any product changes that belong in the release) and push `main`.
4. Run tests:

```bash
xcodebuild -scheme Loadstone -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath /tmp/LoadstoneDerived test
```

Expect `TEST SUCCEEDED`. Do not ship if tests fail.

5. Build Release (arm64, Developer ID, hardened runtime, timestamp):

```bash
xcodebuild -scheme Loadstone -configuration Release -destination 'platform=macOS' \
  -derivedDataPath /tmp/LoadstoneDerived build
```

6. Sign the nested KeyboardShortcuts resource bundle, then re-sign the app. Notarization rejects an unsigned nested bundle even when the outer app verifies:

```bash
IDENTITY="Developer ID Application: Morten Brudvik (3GS65HFAFH)"
APP="/tmp/LoadstoneDerived/Build/Products/Release/Loadstone.app"
ENT="/tmp/LoadstoneDerived/Build/Intermediates.noindex/Loadstone.build/Release/Loadstone.build/Loadstone.app.xcent"

codesign --force --options runtime --timestamp --sign "$IDENTITY" \
  "$APP/Contents/Resources/KeyboardShortcuts_KeyboardShortcuts.bundle"
codesign --force --options runtime --timestamp --entitlements "$ENT" \
  --sign "$IDENTITY" "$APP"
codesign --verify --deep --strict --verbose=2 "$APP"
```

7. Zip with `ditto` (preserves the bundle and signature; do not use `zip`):

```bash
ZIP=/tmp/Loadstone-0.1.2.zip    # match MARKETING_VERSION
ditto -c -k --keepParent "$APP" "$ZIP"
```

8. Notarize and wait until status is `Accepted`:

```bash
xcrun notarytool submit "$ZIP" --keychain-profile "loadstone" --wait
```

On `Invalid`, fetch the log: `xcrun notarytool log <submission-id> --keychain-profile loadstone`. Typical causes: unsigned nested code, missing hardened runtime, missing secure timestamp, `get-task-allow`.

9. Staple the ticket onto the **app** (not the old zip), then re-zip so the download carries the staple:

```bash
xcrun stapler staple "$APP"
xcrun stapler validate "$APP"
spctl --assess --type execute -vv "$APP"
# Expect: accepted / source=Notarized Developer ID
ditto -c -k --keepParent "$APP" "$ZIP"
```

10. Install locally so the maintainer is running the same bits:

```bash
killall Loadstone 2>/dev/null || true
rm -rf /Applications/Loadstone.app
ditto "$APP" /Applications/Loadstone.app
open /Applications/Loadstone.app
defaults read /Applications/Loadstone.app/Contents/Info.plist CFBundleShortVersionString
```

11. Publish. Tag name is `v` + `MARKETING_VERSION`. If a leftover local tag exists (`git tag -l 'v*'`), delete it first (`git tag -d v0.1.2`) so `gh` can create it on `main`. `--target HEAD` is rejected by the API; use `main` after it has been pushed:

```bash
git push origin main
gh release create v0.1.2 "$ZIP" \
  --target main \
  --title "Loadstone 0.1.2" \
  --latest \
  --notes-file - <<'EOF'
Signed with Developer ID and notarized by Apple.

### Get it
Download the zip, unzip, drag Loadstone.app to Applications, then open it.

If snapping fails after upgrading, remove Loadstone from Privacy & Security → Accessibility, add /Applications/Loadstone.app, turn it on, and Relaunch.

### What’s new
- (fill in)
EOF
```

Accessibility TCC is keyed to the code signature. Same Developer ID as the previous install usually keeps the grant; an ad-hoc Debug build does not share it with `/Applications`.

Do not commit app-specific passwords, `.p8` keys, or Keychain exports. The `loadstone` notary profile lives only in the maintainer's Keychain.

Reading the app's logs: `log` is a zsh builtin, so use the full path, and info-level lines (startup summary, hotkey bindings) need `--info`:

```bash
/usr/bin/log show --info --predicate 'subsystem == "com.brudvik.loadstone"' --last 10m
```

Tests run inside the real app as host (`TEST_HOST`), so `AppDelegate.applicationDidFinishLaunching` returns early when `XCTestConfigurationFilePath` is set. Keep it that way: otherwise every test run rewrites the user's WindowManager defaults and may show the Accessibility prompt.

## Architecture

Data flows in one direction: input → `WindowDirector` → `MovableWindow` (AX) → screen geometry.

- **Input.** `HotkeyCenter` registers one global hotkey per `WindowCommand` through the KeyboardShortcuts package (Carbon hotkeys; fire on key-up). `EdgeDragMonitor` owns the NSEvent mouse monitors and the `SnapPreview` overlay but makes no decisions: it feeds events to `DragSnapTracker`, a pure state machine that resolves the window under the pointer only after the drag threshold, arms only once that window's origin has moved (so text-selection and slider drags never snap), and reads the origin only while the pointer is inside a snap zone.
- **Director.** `WindowDirector` runs a `WindowCommand` on a `MovableWindow` and returns a `CommandOutcome`; the no-argument `perform(_:)` overload resolves the focused window, beeps, logs, and triggers the Accessibility prompt. It keeps the restore ledger (first frame per `WindowIdentity`, one-shot restore, pruned when the owning process quits because macOS reuses window ids). Drag snaps pass the display the gesture ended on explicitly; the hotkey path uses the display under the window's centre.
- **AX layer.** `AXWindow` is the only file that handles Accessibility-space (top-left origin) coordinates; everything it exposes is Cocoa space. It validates the window role in its initializer, returns `AXError` from writes instead of swallowing them, wraps every frame write in a save-disable-restore of `AXEnhancedUserInterface`, applies size → position → size (apps clamp a position-first write to the old display), and resolves the private `_AXUIElementGetWindow` SPI with `dlsym` so a missing symbol degrades to a title-based identity. A 0.25s AX messaging timeout is installed at launch.
- **Geometry.** `Tile.frame(in:)` floors the left/bottom pieces and gives the remainder to the right/top ones so complementary tiles meet exactly on odd widths; `leftTwoThirds` is `2 * thirdW` wide for the same reason. `SnapZones` maps a pointer against the *full* screen frame, tiles are laid into the *visible* frame. `ScreenGeometry` flips about the primary display's top edge (`NSScreen.screens[0]`, never `NSScreen.main`). `Display` is a value snapshot of an `NSScreen` so multi-display logic is testable.

### Invariants worth knowing before editing

- `WindowCommand` is the single source of truth for hotkeys, the status-bar menu, and the Shortcuts pane. Adding a `Tile` case fails to compile until `title`, `defaultShortcut`, and `section` cover it, then it appears everywhere. `WindowCommand.id` strings are the UserDefaults keys where users' custom shortcuts live (`KeyboardShortcuts_<id>`); never rename one. `WindowCommandTests` pins the list.
- Swift 6 with `SWIFT_STRICT_CONCURRENCY: complete`. Everything with state is `@MainActor`; the one deliberate `nonisolated` hop is `EdgeDragMonitor.enqueue`. Some Carbon/AX globals (e.g. `kAXTrustedCheckOptionPrompt`) are imported as mutable globals and rejected by the compiler; use their string values instead.
- Testability seams, all with production defaults: `WindowDirector(displays:)`, the `MovableWindow` protocol, `AppSettings(defaults:loginItems:)` via `LoginItemService`, `NativeTiling(defaults:)`, and `DragSnapTracker<Window>` with closures. Extend these rather than reaching for singletons in new code.
- Test fixtures use dimensions that do not divide by 2 or 3 (1201×901, negative-origin displays) on purpose; even fixtures hid a real rounding bug.
- `AppSettings.launchAtLogin` reassigns itself inside a method called from its own `didSet`; the `isApplyingLoginItem` guard is what stops infinite recursion. `SMAppService` can succeed and still report `.requiresApproval`, which the UI surfaces.

### System side effects

- `NativeTiling` writes `EnableTilingByEdgeDrag`/`EnableTopTilingByEdgeDrag` in the `com.apple.WindowManager` defaults domain at launch and restores the user's prior values in `applicationWillTerminate`. A force-quit leaves them off.
- Accessibility (TCC) is keyed to the code signature. Ad-hoc Debug builds get a new identity on every rebuild, which is why the alert and README say to remove and re-add the entry, and why a Debug build and the Developer ID copy in `/Applications` do not share a grant. `AccessibilityAuth.isEffectivelyTrusted` probes a real AX call because `AXIsProcessTrusted` can say yes while calls still return `.apiDisabled` until relaunch.
- KeyboardShortcuts swallows Carbon registration failures (prints to stdout, which an `LSUIElement` app discards) and still records the shortcut as registered; the effective binding per command is logged at startup as the only diagnostic.
